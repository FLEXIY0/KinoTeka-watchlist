# ktw — KinoTeka Watch в терминале

Тот же поиск и те же плееры, что на сайте, но полноэкранным интерфейсом в
терминале и с выводом потока в mpv.

```
╭────────────────────────────────────────────────────────────────╮
│  ▄▄▄▄▄▄▄▄▄▄▄   Игра престолов                                  │
│  ██ обложка ██  Game of Thrones                                │
│  ▀▀▀▀▀▀▀▀▀▀▀   2011 · фэнтези, драма · 55 мин · ★ 9.2          │
│                                                                │
│                Серии                                           │
│                ❯ S2E1  Север помнит              2012-04-01    │
│                  S2E2  Ночные земли              2012-04-08    │
╰────────────────────────────────────────────────────────────────╯
                  ↑↓ выбор  ·  Enter дальше  ·  Esc назад
```

## Установка

ktw входит в КиноТеку и ставится вместе с ней — см. [README КиноТеки](../README.md#установка-и-запуск).
На Windows это одна команда в PowerShell:

```powershell
irm https://raw.githubusercontent.com/FLEXIY0/KinoTeka-watchlist/main/install.ps1 | iex
```

После неё в любом терминале: `ktw watch` — плеер, `ktw матрица` — сразу фильм, просто `ktw` — коллекция.
Из исходников: `npm install`, затем `node scripts/kinoteka.js watch`.

Нужны Node.js 20+ и [mpv](https://mpv.io) (установщик ставит mpv через winget).

Всё, что посмотрено в ktw, само попадает в коллекцию КиноТеки: сериал — после первой
серии, фильм — как начатый или досмотренный. Ключ Кинопоиска общий: введённый в поиске
на главной странице КиноТеки работает и здесь.

## Как пользоваться

```sh
ktw                          # полноэкранный интерфейс
ktw матрица                  # сразу с запросом в поле поиска
ktw 301                      # по id Кинопоиска
ktw https://www.kinopoisk.ru/film/301/
```

Дальше всё интерактивно: печатаешь название — под полем появляются похожие
фильмы, Enter выбирает. Для сериала спросит сезон и серию, потом плеер, потом
озвучку (если их несколько — у Alloha и Collaps их бывает под два десятка),
достанет поток, спросит качество и отдаст всё это mpv. После выхода из mpv возвращает к
списку серий, так что следующую можно включить в два нажатия.

| Клавиши | Действие |
| --- | --- |
| `↑` `↓` | выбор в списке |
| `PgUp` `PgDn` `Home` `End` | быстрая прокрутка длинных списков |
| `Enter` | дальше |
| `Esc` | шаг назад, из поиска — выход |
| `Ctrl+U` `Ctrl+W` | очистить поле / стереть слово |
| `Ctrl+C` | выход отовсюду |

### Опции

| Опция | Что делает |
| --- | --- |
| `-p, --player <тип>` | взять плеер по имени, без выбора вручную |
| `-t, --translation <имя>` | взять озвучку по части названия |
| `-q, --quality <n>` | качество: `1080`, `720`, `max`, `min` |
| `-s, --season <n>` | номер сезона |
| `-e, --episode <n>` | номер серии |
| `--iframe` | не искать поток, просто вывести ссылку на плеер |
| `--no-mpv` | найти поток и вывести ссылку с готовой командой mpv |
| `--json` | машинный вывод для скриптов |
| `--plain` | построчный режим без полноэкранного интерфейса |
| `--doctor` | проверить, что именно не работает, и подсказать, чем лечить |
| `--timeout <мс>` | сколько ждать поток, по умолчанию 40000 |
| `--key <ключ>` | ключ API Кинопоиска |

Всё после `--` уходит напрямую в mpv:

```sh
ktw матрица -- --fs --sub-file=ru.srt
```

Флаги `--json`, `--no-mpv`, `--iframe`, `--plain` и запуск без терминала
переключают в построчный режим: служебный вывод идёт в stderr, ссылка и JSON —
в stdout, поэтому пайпы работают.

```sh
ktw матрица --no-mpv | xargs -I{} yt-dlp {}
```

### Ключ API — не обязателен

Без ключа клиент работает сразу: название уходит прямо в Kinobox, который умеет
искать по нему сам. Смотреть можно, но не будет выбора среди похожих фильмов,
обложек, описаний и списка сезонов с сериями — Kinobox отдаёт только плееры.
Сезон и серию в этом режиме задают флагами `-s` и `-e`.

Ключ всё это добавляет. Бесплатный выдаёт
[kinopoiskapiunofficial.tech](https://kinopoiskapiunofficial.tech), регистрация
занимает минуту, а вставить его можно прямо в интерфейсе по `Ctrl+K` — он
сохранится в `~/.config/ktw/config.json`.

Берётся, в порядке приоритета, из:

1. `--key <ключ>`
2. переменной окружения `KINOPOISK_API_KEY`
3. файла `kinopoisk-key.js` в корне проекта (того же, что использует сайт локально)
4. `~/.config/ktw/config.json`

### Переменные окружения

| Переменная | Смысл |
| --- | --- |
| `KTW_POSTER=off` | не рисовать обложки |
| `KTW_ASCII=1` | рамки и спиннеры из ASCII вместо Unicode |
| `NO_COLOR=1` | без цвета |
| `KTW_KINOBOX_API` | своё зеркало списка плееров |
| `KTW_RUNTIME` | `bun`, `node` или `auto` — чем запускать клиент |
| `KTW_NO_CACHE=1` | не кешировать ответы API |

## Как это работает

Сайт использует `kinobox.js`, который дёргает `api.kinobox.tv/api/players?kinopoisk=<id>`
и получает список балансеров с адресами iframe. CLI повторяет ту же цепочку:

```
запрос ─► kinopoiskapiunofficial.tech  ─► выбор фильма, сезона, серии
       ─► fbphdplay.top/api/players    ─► выбор плеера и озвучки
       ─► прямой разбор балансера      ─► забираем адрес мастер-плейлиста
       ─► mpv                          ─► смотрим
```

### Качество и звук

Балансер отдаёт один адрес мастер-плейлиста, а внутри него несколько дорожек.
Клиент читает плейлист и показывает список (`1080p · 4200 кбит/с`,
`720p · 2100 кбит/с`, …). Прошлый выбор подставляется заранее, так что на
следующей серии достаточно Enter.

Важная деталь, из-за которой раньше пропадал звук: озвучки лежат **не внутри**
дорожки качества, а отдельными рендициями:

```
#EXT-X-STREAM-INF:BANDWIDTH=1660089,RESOLUTION=1280x534,AUDIO="audio720"
/…/index-v1.m3u8                                    ← только видео, без звука
#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="audio720",NAME="02. Дубляж (RUS)",URI="/…/index-a2.m3u8"
```

Клиент раньше подставлял в mpv адрес `index-v1.m3u8` — картинка шла, звука не
было вовсе. Теперь mpv всегда получает **мастер-плейлист**, качество задаётся
через `--hls-bitrate`, а озвучка — через `--aid` по номеру внутри группы этого
качества. Номер сверяется с реальным списком дорожек: `--aid` на несуществующую
дорожку mpv отрабатывает молча и снова без звука.

### Какая дорожка играет

`--aid` считается по документированной привязке балансера. У Collaps в конфиге
плеера лежит `audio: {names: [...], order: [...]}`, где `order` — это номер
рендиции `index-aN.m3u8`, то есть `--aid = order + 1`:

```js
audio: { names: ["Дубляж", "LostFilm", "Оригинал (ENG)"], order: [1, 2, 0] }
//                                      ^^^^^^^^^^^^^^^^         ^^^ order 0 → дорожка №1
```

Отсюда и брался английский звук: у оригинала `order: 0`, то есть он стоит
**первой** дорожкой, и mpv без явного `--aid` играл именно её.

Язык дорожки определяется отдельно от названия. Атрибута `LANGUAGE` балансеры
не проставляют вовсе — язык зашит в само название: `02. Дубляж (RUS)`,
`17. Оригинал (ENG)`, `16. Многоголосый. 1+1 (UKR)`. Раньше суффикс просто
вырезался при сравнении, и «Оригинал (ENG)» совпадал с русским «Оригинал».
Теперь дорожки разных языков не подменяют друг друга, а когда название не
совпало ни с чем — берётся русская дорожка, а не первая попавшаяся.

Если мастер-плейлист прочитать не вышло, экран показывает настоящую причину
(«HTTP 403 — обычно чужой Referer или регион»). Раньше в этом случае
подставлялась метка из ответа Kinobox — и поломка выглядела как «качество
1080p» на любом фильме. Когда закрыт `hls`, клиент пробует лежащий рядом `dash`.

Экран показывается всегда, даже когда балансер отдал одну дорожку — тогда в
списке будет «как есть» с его же меткой качества. Пропуская экран, клиент решал
за пользователя и выглядел сломанным. То же и с озвучкой: если балансер их не
разделяет, в списке будет «по умолчанию», но выбор всё равно предлагается.

Мастер-плейлист предпочитается медиа-плейлисту: если первым прилетела
одиночная дорожка, клиент ждёт ещё полторы секунды — вдруг следом придёт
мастер с качествами.

### Как отсеивается реклама

Преролл на балансерах идёт первым, поэтому «берём первый пойманный медиа-адрес»
отдавало именно рекламу. Теперь иначе:

- рекламные сети, счётчики и SDK (IMA, adfox, adriver и ещё пара десятков)
  режутся на уровне сети — ролику обычно нечем даже запуститься;
- каждый пойманный плейлист проверяется по содержимому: сумма `#EXTINF`
  короче пяти минут при наличии `#EXT-X-ENDLIST` — это ролик, а не серия;
- мастер-плейлист с дорожками принимается сразу, такого у рекламы не бывает;
- пока контент не найден, ожидание продолжается, а на экране видно, что
  происходит: «пропустил рекламный ролик на 24 с, жду дальше».

Если за отведённое время пришла только реклама, клиент об этом скажет прямо и
предложит другой балансер, а не выдаст ролик за фильм.

### Скорость извлечения

Браузера нет, поэтому извлечение — это один-два HTTP-запроса и разбор ответа:
доли секунды вместо десятков секунд на старт Chromium и ожидание манифеста.

### Буфер и кеш

Два разных кеша, и раньше оба работали плохо.

**Буфер воспроизведения.** mpv запускался с `--cache=yes`,
`--demuxer-max-bytes=250MiB` и `--demuxer-readahead-secs=180` — выглядит
внушительно, но не работает: при включённом кеше `--cache-secs` **перебивает**
`--demuxer-readahead-secs`, а по умолчанию он равен 10 секундам. Буфер в 250 МиБ
стоял почти пустым, и на медленном канале видео замирало на каждом сегменте.
Теперь `--cache-secs=300` выставлен явно, плюс `--stream-buffer-size=8MiB`,
чтобы сегменты HLS качались пачкой.

**Кеш ответов API.** Его не было вовсе: каждый заход в фильм заново дёргал
Кинопоиск и Kinobox. Теперь ответы лежат в `~/.cache/ktw/api` с разным сроком
годности — описания и сезоны сутки, список плееров четверть часа, потому что в
ссылках на iframe лежат недолгие токены. Пустой ответ не кешируется, иначе одна
неудача залипала бы до истечения срока. Выключается через `KTW_NO_CACHE=1`,
чистится через `ktw --clean`.

На стенде с рекламой, восемью картинками и отложенным плеером это дало
5.3 с → 1.8 с на повторных запусках.

### Зеркала списка плееров

`api.kinobox.tv` отвечает не отовсюду: с части адресов он рвёт соединение или
отдаёт 5xx. Поэтому первым опрашивается `fbphdplay.top/api/players` — то самое
зеркало, с которого сайт грузит `kinobox.js`, и отдаёт оно ровно тот же JSON.
Если оно молчит, следующим идёт официальный `api.kinobox.tv`; своё зеркало
можно поставить первым через `KTW_KINOBOX_API`.

Ответ богаче, чем кажется: у каждого балансера свой список озвучек, и у части
из них (Alloha, Veoveo) **у каждой озвучки собственная ссылка на iframe** —
`&translation=93` и так далее. Поэтому озвучка выбирается до извлечения потока,
а не переключается внутри плеера.

### Балансеры

Chromium не используется: у каждого балансера свой разбор.

| Балансер | Как достаётся поток |
| --- | --- |
| Collaps | конфиг `makePlayer({…})` прямо в HTML — плейлист, серии, озвучки, субтитры |
| Veoveo | со страницы берутся `ENV_BASE_URL` и заголовки `DLE-API-TOKEN` / `Iframe-Request-Id`, затем `GET {base}/catalog-api/episodes?content-id=<id>` отдаёт `episodeVariants[].filepath` |
| Alloha | `fileList` из HTML, затем `POST /lists.php` с `id` и `token` |
| Kodik | `POST /ftor` с подписями из `urlParams`, ответ раскодируется base64 со сдвигом (сдвиг подбирается перебором — они его меняют) |
| Turbo и прочие | общий проход: поиск `.m3u8`/`.mpd` в HTML и спуск на один вложенный iframe |

`Iframe-Request-Id` у Veoveo нельзя выдумать: он вшит в подписанный путь
плейлиста, поэтому заголовки берутся только со страницы плеера.

Referer и User-Agent обязательны на каждом шаге, включая mpv, — без них CDN
отдаёт 403. Реклама и превью отсеиваются по маске адреса.

### Когда балансер отказывает

Отказ по региону выглядит как HTTP 410 или 404 со страницей «контент недоступен
в вашем регионе». Раньше это молча превращалось в «поток не найден», и было не
отличить закрытый регион от сломанного парсера. Теперь причина доходит до
экрана как есть, а `ktw --doctor` проверяет все балансеры разом.

## «Обновился, а ничего не изменилось»

Самая частая причина — запускается другая ветка или старый клон. Установщик по
умолчанию тянет ветку `feature/direct-kinobox-tui` (`KTW_BRANCH` её меняет), и
если правки лежат в другой ветке, обновление их не подхватит.

Проверяется одной командой:

```sh
ktw --doctor
```

```
  ✓ версия — установщик a1b2c3d
  ✗ правки на месте — запущена старая копия — нет: выбор русской озвучки, буфер воспроизведения
      обнови: ktw update
```

Пункт «правки на месте» проверяет не дату и не номер версии, а наличие самих
функций в запущенном коде — так видно, что копия действительно свежая. Симптомы
устаревшей копии («нет выбора качества», «озвучка английская», «балансеры не
работают») выглядят ровно так же, как настоящая поломка, поэтому гадать по ним
бесполезно.

## Что-то ведёт себя странно после обновления

```sh
ktw --clean
```

Команда печатает, какая версия и откуда запускается, сверяется с origin
(отставшая копия — самая частая причина «не работает») и чистит кэш обложек.

Неизвестный флаг больше не считается названием фильма — если `ktw --clean`
отвечает «неизвестный флаг», значит запускается старая копия.

## Не появляется выбор качества или озвучки

Оба экрана показываются всегда. Если выбирать не из чего, в списке будет одна
строка — «как есть» или «по умолчанию». Что реально предлагает балансер, видно
так:

```sh
ktw "сверхъестественное" -s 6 -e 17 --json --no-mpv | grep -A5 translations
```

## `ktw: команда не найдена`

На Windows установщик добавляет `%LOCALAPPDATA%\KinoTeka\bin` в PATH пользователя.
Уже открытые окна терминала об этом не знают — откройте новое окно. Проверить,
что сама команда на месте:

```powershell
& "$env:LOCALAPPDATA\KinoTeka\bin\ktw.cmd" help
```

Если раньше стоял ktw от KinoTeka-Watch (в `%USERPROFILE%\.local\bin`), новый
стоит в PATH раньше него; старый можно удалить.

## Если поток не нашёлся

Сначала — доктор, он проверит всё по цепочке и скажет, где оборвалось:

```sh
ktw --doctor
```

```
Доктор ktw
  ✓ рантайм — node v24.22.0
  ✓ mpv — mpv 0.37.0
  ✓ браузер — не нужен, всё берётся прямым парсингом
  ✓ ключ Кинопоиска — задан (a1b2…f9e0)
  ✓ список плееров — fbphdplay.top отвечает
  ✓ балансер Collaps — vn50007.mvapspdmpg.com
  ! балансер Alloha — theatre.stravers.live: контент недоступен в твоём регионе
  ! регион — часть балансеров закрыта для твоего IP
      включи VPN или прокси с российским адресом
```

Дальше по обстоятельствам:

- «недоступно в твоём регионе» — нужен VPN или прокси с адресом РФ, флаги не помогут
- «соединение сброшено» у всех зеркал — домены режет провайдер, помогает VPN или
  своё зеркало через `KTW_KINOBOX_API`
- балансер отказал в одиночку — попробовать другой, их в списке обычно несколько
- не заработало нигде — открыть плеер как есть: `--iframe`

Быструю локальную проверку (рантайм, mpv, ключ, права на конфиг) ktw делает при
каждом запуске сам и молчит, пока всё на месте. Установщик в конце делает то же
самое — печатает только то, что нужно поправить.

## Тесты

```sh
node ktw/test.js            # офлайн: разбор балансеров, звук, качества, доктор
node ktw/test.js --live     # плюс живые балансеры
node ktw/test.js --only=звук
```
